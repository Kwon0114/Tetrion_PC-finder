# Tetrion PC Finder

[한국어](README.md) · [English](README.en.md)

테트리스 **퍼펙트 클리어(PC)** 를 찾고, 그 **확률**까지 정확하게 계산하는 브라우저용 도구입니다.
HTML 파일 하나로 동작하며 서버·설치가 필요 없습니다. 폰과 PC 브라우저 모두에서 쓸 수 있고, 한국어와 영어 화면을 지원합니다(우측 상단 `EN`).

웹앱이기 때문에 극도로 가볍습니다.

## 빠른 시작

1. HTML 파일을 브라우저로 엽니다.
2. **보드**에 이미 쌓인 블록을 칠하고 **높이**를 맞춥니다.
3. **넥스트**에 큐를 입력합니다. 예: `[IOTSZJL]!` 또는 `SZTOJLIOSZ`. `랜덤 2백` 버튼으로 7-bag 두 개를 자동으로 채울 수 있습니다.
4. **PC 찾기** 탭에서 `퍼펙트 클리어 찾기`를 누릅니다.
5. 결과의 확률, 해법 목록, 해법 재생을 확인합니다.

> **오프라인**
> 모든 코드가 HTML 파일 하나에 들어 있고 외부 폰트·스크립트를 불러오지 않으므로, 파일을 그대로 열면 인터넷 없이 동작합니다.
> 웹(예: GitHub Pages)에 올릴 때는 `sw.js`, `manifest.webmanifest`, `icon.svg`를 `index.html`과 같은 폴더에 두세요. 서비스 워커가 페이지를 캐시해 첫 방문 이후에는 오프라인으로도 열리고, 홈 화면에 설치할 수도 있습니다. (온라인이면 항상 최신 버전을 먼저 받아 옵니다.)

## 보드 편집

- 칸을 눌러 블록을 칠하고 지웁니다. 터치 드래그로 여러 칸을 한 번에 칠할 수 있습니다.
- **높이**는 `−` / `+` 버튼이나 숫자 입력으로 조절합니다. (PC 찾기 최대 12줄, 구축 확률 모드 최대 23줄)
- **색칠 팔레트**로 피스 색을 지정할 수 있고, 해법을 보드에 적용할 때 색이 그대로 유지됩니다.
- **비우기**로 보드를 초기화합니다.
- **보드 여러 개**를 만들고 번호를 붙여 관리합니다. 보드 칩을 누르면 해당 보드로 이동하고, 선택된 칩을 한 번 더 누르면 번호를 바꿀 수 있습니다. `복제`, `삭제`를 지원합니다. (최대 20개)

## 넥스트(큐) 입력 문법

피스는 `I O T S Z J L` 일곱 글자입니다. 대소문자는 구분하지 않습니다.

### 기본

| 입력 | 의미 |
|---|---|
| `SZTOJLI` | 이 순서대로 고정된 큐 |
| `[TIL]` | T·I·L 중 **1개** |
| `[TIL]2` | 쓴 순서를 유지하며 2개 뽑기 (TI·TL·IL) |
| `[TIL]!` | 3개 전부 **섞어서** |
| `[TIL]2!` | 3개 중 2개를 뽑아 **섞어서** |
| `[]!` | `[IOTSZJL]!` 와 같음, 7-bag |
| `[]3!` | 7-bag에서 앞 3개만 |

- `[ ]` 안에는 띄어 써도 되고, **중첩**할 수 있습니다. 예: `[[SZ]! [LJ]!]2!`
- 숫자는 `!`, `%`보다 **앞에** 씁니다. 예: `[IOTSZJL]3!`
- `%`는 bag 여부를 뒤집습니다. 일반 묶음에 붙이면 bag으로 지정되고, `[]`에 붙이면 해제됩니다.
- 입력 중 `[`를 치면 `]`가 자동으로 붙고, `SZ]` 처럼 닫는 괄호만 쓰면 `[SZ]`로 감싸 줍니다. `{ }`도 마찬가지입니다. (규칙은 [알고리즘 13](#13-자동입력-큐-입력칸) 참고)

### 순서 조건 `{ }`

묶음 바로 뒤에 붙여 **그 묶음 안의 순서**를 제한합니다.

| 입력 | 의미 |
|---|---|
| `{LJ<SZ}` | L·J가 모두 S·Z보다 앞 (나머지는 자유) |
| `{SZ>LJ}` | 위와 같은 뜻 |
| `{A<B<C}` | 체인, A가 B보다 앞이고 B가 C보다 앞 |
| `{A<B,C<D}` | 쉼표로 규칙 여러 개 |

예: `[szljtt]!{tt>z}`는 S·Z·L·J·T·T를 섞되 두 T가 모두 Z보다 뒤인 큐만 남깁니다(360가지에서 120가지).

주의할 점:

- 조건은 **바로 앞 묶음에만** 적용됩니다. `T[]!{t>j}`에서 맨 앞 `T`는 조건과 무관합니다.
- 조건을 만족하는 큐만 남기고 확률은 다시 정규화됩니다.
- `{ }`는 묶음 하나에 한 번만 붙일 수 있습니다. 규칙이 여러 개면 쉼표로 이어 씁니다.
- 서로 다른 묶음의 피스끼리 비교하려면 둘을 감싸는 바깥 묶음에 조건을 붙입니다.
- 만족하는 큐가 없으면 오류로 알려 줍니다.

### 경고

계산은 계속 진행되지만, 의도와 다를 수 있는 입력은 입력칸 아래에 금색 `⚠` 로 알려 줍니다.

- 순서 조건에 **묶음에 없는 피스**를 쓴 경우: 그 피스는 무시됩니다.
- **일부만 뽑는** 묶음에 순서 조건을 쓴 경우: 뽑히지 않은 피스는 조건에서 빠집니다.

## PC 찾기

보드와 큐가 주어졌을 때, **퍼펙트 클리어로 끝나는 모든 해법**을 찾고 큐 전체에 대한 **성공 확률**을 계산합니다.

- 큐에 `[ ]`가 있으면 가능한 모든 경우를 가중치(확률)와 함께 전개합니다. 중복되는 큐는 정확히 합쳐집니다.
- 채운 칸 + 4×피스 수 = 10×줄 수가 되는 경우만 의미가 있으므로, 불가능한 보드와 넥스트가 모자라는 경우는 이유를 알려 줍니다.
- PC에 영향을 주는 앞쪽 피스만 계산합니다. 홀드를 쓰면 한 개 더 봅니다.
- **See** 값으로 "볼 수 있는 넥스트 수"를 제한한 계산(플레이어 시점의 확률)도 가능합니다.
- 탐색은 바닥 **8줄**까지 지원합니다. 8줄 위에 블록이 있으면 안내가 나옵니다.

## 결과 화면

- **성공 확률**과 계산에 쓴 경우의 수
- **해법 목록**: 해법마다 `세이브`(홀드에 남기는 미노) 구분, 선택해 해당 해법만 보기
- **해법 재생**: `◀ 재생 ▶`로 한 수씩 확인
- **PC 후 남는 bag 미노** 통계 (최소 해법 기준 포함)
- **실패 큐** 목록 (확률 높은 순)
- **후멘 복사**: 보고 있는 해법을 후멘 코드로 복사
- 결과는 보드·옵션이 같으면 저장되어 다시 열 수 있습니다.

## 셋업 파인더

`옵션`의 **셋업 파인더**를 켜면 `찾기` 버튼이 PC 대신 **앞쪽 N피스로 쌓는 셋업**을 찾습니다.

- **피스** 입력으로 셋업에 쓸 피스 수(1~9)를 정합니다.
- **사용 미노**: 각 미노를 눌러 `사용 필수 ✓` → `사용 금지 ✕` → 해제 순으로 바꿉니다. 필수로 지정하는 미노는 셋업 피스 수를 넘을 수 없습니다.
- 높이 제한 없이 쓸 수 있습니다. (엔진 한도는 PC 찾기와 같은 8줄)
- 결과는 **50개씩 묶음**으로 접고 펼칠 수 있고, 최대 300개까지 보여 줍니다.
- 셋업마다 "자세히", "보드에 적용"(편집 중인 보드 / 기존 보드 / 새 보드 선택)이 있습니다.
- 셋업이 있을 때 PC로 이어질 확률(조건부 확률)도 계산합니다.

## 구축 확률 (셋업 구축 모드)

보드 모양을 **목표 셋업**으로 두고 "이 큐로 그 모양을 쌓을 수 있는 확률"을 계산합니다.

- **보드마다 설정**을 배정합니다. 설정에는 넥스트, 홀드, 조건이 저장됩니다.
- **조건**: T스핀 / T스핀 싱글·더블·트리플 / 쿼드 / 올스핀(TETR.IO 전용). 개수를 지정할 수 있습니다.
- **합집합 / 교집합** 스위치: 여러 보드 중 하나라도 되는지(합집합), 모두 되는지(교집합)를 선택합니다.
- 계산 전에 체크한 보드만 대상으로 할 수 있습니다(아무것도 체크하지 않으면 전체).
- 결과: 총 구축 확률, 보드별 확률, **쌓을 수 없는 큐**(확률 높은 순), 예시 해법.
- 보드 높이는 최대 23줄까지 입력할 수 있습니다.
- 백투백을 켜면 백투백을 유지한 채 구축하는 확률도 함께 보여 줍니다.

## 점수 계산

선택한 모드(**Jstris** 또는 **TETR.IO Blitz**)의 점수표로 해법 점수와 평균을 계산합니다.

- 레벨 1 고정
- 줄 삭제 점수: 싱글 100 / 더블 300 / 트리플 500 / 쿼드 800, 미니 더블 400, 올클리어 3500 등
- T스핀, 백투백 ×1.5, 콤보 +50×콤보, PC +3000 등의 보너스

모드별 정확한 표는 `평균 점수` 옵션의 툴팁에 표시됩니다.

## 후멘 가져오기·내보내기

- **가져오기**: 후멘 코드(`v115@…`)를 붙여넣으면 **페이지마다 보드 1개**로 만들어 줍니다. 지형은 알아서 나뉩니다.
- **내보내기 / 후멘 복사**: 현재 필드나 해법을 후멘으로 복사합니다.
- 구축 확률 모드에서는 23줄까지의 후멘을 가져올 수 있습니다. PC 찾기에서는 12줄까지입니다.

## 알고리즘

전체 흐름은 다음과 같습니다.

```
큐 문법 해석 → (가중치가 붙은) 큐 경우의 수
      ↓
 scan → cull → place   : PC가 되는 모든 "피스 조합(해법)" 찾기
      ↓
 큐 검사               : 어떤 큐가 어떤 해법으로 실제 플레이 가능한지 판정
      ↓
 확률 / 최소 해법 / 세이브 / 실패 큐 / 점수 / 백투백 통계
```

### 1. 보드 표현

- 한 줄을 **10비트 정수**로 표현합니다. 충돌 검사, 줄 삭제, 위치 판정이 모두 비트 연산(AND, 시프트)입니다.
- 한 보드는 5줄씩 숫자 하나(double에 정확히 들어감)로 묶어 `K1, K2, K3` 키로 만듭니다.
- 한 탐색 단계의 보드들은 **타입 배열**에 담깁니다. 보드 테이블(오픈 어드레싱 해시), 보드별 줄 삭제 수·생존 여부·큐 상태(연결 리스트 풀)·이전 보드로 가는 간선(연결 리스트)을 보드당 약 40바이트로 저장해, 객체/Set 기반보다 메모리를 크게 아낍니다.

### 2. 착지 위치 생성 (비트 병렬)

- 피스·회전마다 줄 마스크를 미리 만들어 두어 충돌 검사는 몇 번의 AND로 끝납니다.
- 회전 `r`, 높이 `y`마다 마스크 하나가 **모든 열을 한꺼번에** 나타냅니다.
  - `valid[r][y]`: 그 높이에서 피스가 들어갈 수 있는 열
  - `reach[r][y]`: 실제로 도달할 수 있는 열
- 소프트 드롭은 다음 줄의 `valid`와 AND 한 번, 좌우 이동은 **시프트-AND 플러드**, 회전은 킥 테스트를 순서대로 모든 열에 동시에 적용합니다(이미 킥을 찾은 열은 제외).
- 블록 더미 위쪽은 자유롭게 움직일 수 있으므로 그 구간은 낙하만 계산해 시간을 줄입니다.
- **킥 테이블**: TETR.IO SRS+(대칭 I 킥, 방향별 180° 킥)와 Jstris 가이드라인 SRS를 지원합니다. 180° 킥은 테스트별로 켜고 끌 수 있습니다.
- **스핀 판정**: 마지막 동작이 회전이고 좌·우·위로 움직일 수 없는 자리를 스핀 착지로 봅니다. T는 4모서리 중 3개가 막혀도 인정하며, 5번째 킥(1×2 이동)을 쓴 T 회전은 앞 모서리가 다 차 있지 않아도 정식 T스핀으로 봅니다.
- 도달 가능한 착지 위치는 (쌓인 아래쪽 줄, 피스, 180° 설정)을 키로 **캐시**하고, 실행이 끝나도 유지됩니다.

### 3. scan / cull / place (해법 찾기)

해법 후보를 큐와 무관하게 먼저 모두 찾고, 큐는 나중에 해법에 대해 검사합니다.

1. **scan**: 시작 보드에서 피스를 한 개씩 놓으며 단계별로 전진합니다. 보드는 **줄 삭제 후** 상태로 저장하므로 같은 보드는 합쳐집니다. 각 보드는 "어떤 큐 상태로 도달할 수 있는지"와 "어느 보드에서 왔는지(이전 간선)"를 기억합니다.
2. **cull**: 최종(빈) 보드에서 거꾸로 걸어, PC로 이어지는 보드만 남깁니다.
3. **place**: 남은 보드만 다시 scan하되 이번에는 **어떤 피스를 놓았는지** 기억합니다. 줄이 먼저 지워진 뒤에 놓은 피스는 지워진 줄 때문에 쪼개질 수 있어, 줄이 지워지지 않은 것으로 펼친 "그림"으로 복원합니다. 살아남은 피스 조합 하나하나가 **해법**입니다.

**가지치기 (`illegalBoard`)** — 절대 채울 수 없는 보드를 즉시 버립니다.

- 가로로 완전히 갇힌 열은 세로 I만 들어갈 수 있으므로, 그 열의 빈칸 수가 4의 배수여야 합니다.
- 모든 줄에서 인접한 두 열 중 하나가 차 있으면 피스가 두 열 사이를 넘나들 수 없으므로(줄은 가득 차야만 사라짐), 양쪽 빈칸 수가 각각 4의 배수여야 합니다.
- 빈칸이 정확히 4개 남았다면 그 칸들이 하나로 연결된 테트로미노 모양이어야 합니다.

### 4. 큐 상태와 홀드

- 큐 상태는 **13비트**(현재 bag에서 아직 안 나온 피스) + **3비트**(홀드 칸의 피스)입니다.
- 한 단계에서 뽑은 피스는 "그대로 놓기" 또는 "홀드와 교체"가 됩니다. 홀드를 끄면 홀드 칸은 큐를 한 피스 늦출 뿐이므로 교체만 허용합니다.
- 큐 상태의 결과는 보드와 무관해서 **단계별 캐시**에 한 번만 계산합니다.
- `bagSpecs`가 앞쪽 m개 피스를 bag 단위로 설명합니다. 한 bag로 표현이 안 되면 자리마다 나올 수 있는 피스를 모두 담은 단일 뽑기로 느슨하게 설명합니다. scan이 느슨해질 뿐이고, 모든 큐는 이후 정확히 검사하므로 결과는 같습니다.

### 5. 큐 검사 (확률 계산)

- 각 해법에 대해 **실제로 둘 수 있는 놓는 순서**(스핀·탁·줄 삭제 포함)를 모읍니다(`orderSet`). 큐의 bag·홀드가 낼 수 있는 순서만 만들기 때문에 불가능한 순서는 아예 생성되지 않습니다.
- 가능한 순서의 접두사는 **트라이**로 저장해, 한 단계가 문자열 생성 없이 배열 조회 한 번이 됩니다.
- 큐 하나에 대한 판정은 "놓은 순서 + 홀드 중인 피스의 큐 위치"를 상태로 하여, 어떤 해법의 어떤 순서로든 끝까지 플레이할 수 있으면 성공입니다.
- **같은 순서 집합**을 쓰는 큐들은 같은 해법으로 풀리고 점수도 같으므로, 순서 집합마다 한 번만 계산하고 큐는 가중치만 더합니다.
- 해법 목록만 필요하면, 모든 해법이 자기를 플레이하는 큐를 하나씩 얻는 순간 중단합니다.

### 6. 큐 경우의 수 전개

- 묶음은 요소(피스 또는 하위 묶음)를 뽑는 모든 선택이 **같은 확률**이며, 중복되는 큐는 정확히 합산됩니다.
- 모든 큐는 **혼합 기수 인덱스**로 필요할 때 생성하므로 경우의 수가 아무리 많아도 한꺼번에 메모리에 올리지 않습니다.
- `estOptions`가 열거 없이 경우의 수 상한을 계산해, `[[][][][][][][][][][]]!` 같은 입력은 페이지가 멈추기 전에 거절합니다.
- 탐색은 큐의 **앞쪽 m개 피스**만 봅니다. 앞 m개가 같은 큐는 한 경우로 합치고, 경계에 걸친 묶음의 선택지는 가중치를 더해 합칩니다.
- `{ }` 순서 조건은 선택지를 만든 뒤 조건을 만족하는 것만 남기고 가중치를 다시 정규화합니다.

### 7. 최소 해법 집합

"가장 적은 해법으로 PC가 되는 모든 큐를 덮는" 집합을 **정확한 최소 히팅 셋**으로 구합니다.

1. **축소 규칙**: 해법이 하나뿐인 그룹은 그 해법을 강제 선택 → 다른 해법이 모든 그룹을 포함하는 해법은 제거 → 다른 그룹을 포함하는 그룹은 제거. 더 줄일 수 없을 때까지 반복합니다.
2. 해법을 공유하지 않는 **독립 성분**으로 나눠 각각 풉니다.
3. 성분마다 **반복 심화**로 크기 k = 1, 2, …를 시도합니다(탐욕 해가 상한). 처음 성공한 k가 증명된 최소입니다. 후보가 가장 적은 미해결 그룹에서 분기하고, 앞선 형제 분기는 뒤 분기에서 금지합니다.
4. **하한**: (A) 가장 많이 덮는 r개의 합이 부족하면 가지치기, (B) 서로 겹치지 않는 미해결 그룹은 각자 해법이 필요합니다.
5. 시간 제한을 넘으면 중단하고 그때까지의 최선을 쓰며 "정확하지 않음"으로 표시합니다.

표시 순서는 큐 가중치가 큰 순이며, 같으면 스핀이 많은 해법이 먼저입니다.

### 8. 통계

- **세이브**: 마지막 bag에서 해법이 쓰지 않은 피스. 그 이전 bag은 통째로 뽑힌 경우에만 계산할 수 있고, 아니면 알 수 없음(`[]`)입니다.
- **실패 큐**: 어떤 해법으로도 못 푸는 큐와 그 확률.
- **백투백 유지**: 줄 삭제가 쿼드·스핀·PC뿐인 해법만으로 같은 계산을 다시 합니다.
- **점수**: 해법의 놓는 순서를 정하는 **부분집합 DP**로 최고 점수를 구합니다. 같은 종류 피스는 역할을 바꿀 수 있고, 줄 삭제·스핀 판정은 (해법, 피스) 단위로 한 번만 계산합니다. 한 번의 플레이에서 가능한 줄 삭제 유형 조합도 비트마스크로 모아 최대 집합만 남깁니다.

### 9. See N (볼 수 있는 넥스트 제한)

플레이어가 현재 피스와 다음 N개(그리고 홀드)만 보고 최선을 둔다고 가정한 **기댓값 최대화(expectimax)** 입니다.

- 상태는 `보드, 홀드(없음/피스), 방금 홀드 여부, 보이는 피스 창, 아직 모르는 부분`입니다.
- 모르는 부분은 큐 자체의 분포를 따르며(큐 요소는 서로 독립), bag처럼 순서만 다른 상태는 **교환 가능**해 같은 캐시 값을 씁니다.
- 확률만 구할 때는 같은 단계·같은 줄의 보드가 캐시를 공유하는 **빠른 경로**를 씁니다.
- 최적 정책을 따라 걸으며 해법별 확률, 예시 플레이, 남는 bag 피스, 실패 접두사를 얻습니다. 최소 해법 집합은 최적 플레이가 쓴 해법에서 시작해, 확률이 그대로인 동안 가능성이 낮은 해법부터 하나씩 빼는 방식입니다.
- 메모리가 너무 커지면 상세 분석을 포기하고 확률만 계산합니다.

### 10. 셋업 파인더

플레이어가 **셋업 S(앞 N개를 놓은 뒤의 보드)** 를 목표로 삼아, 보이는 피스(현재 + 다음 N개 + 홀드)로 S를 만들고, 그다음부터 일반 See 값으로 플레이한다고 가정합니다.

- `weight(S) = Σ 시작 상태 확률 × S를 만드는 방법 중 최선의 값`
- **조건부 확률**: P(PC | S가 쌓임) = (S를 거쳐 PC에 도달하는 큐) ÷ (S를 쌓을 수 있는 큐).
- 사용 미노 필터(필수/금지)는 탐색 중에 적용되므로 순위가 상위 후보뿐 아니라 **조건에 맞는 모든 셋업**에 대해 매겨집니다.
- 셋업 키는 5줄까지 정확히(줄당 10비트) 만들고, 6줄 그림(60비트)은 double에 안 들어가 53비트로 해시합니다.

### 11. 구축 확률 (셋업 구축 모드)

보드마다 사양(넥스트, 홀드, 조건)을 두고, 큐 하나마다 목표 보드를 쌓을 수 있는지와 조건(T스핀·쿼드 등)을 만족하는지를 판정합니다. 보드별 결과를 모아 **합집합**(하나라도) 또는 **교집합**(모두)으로 합치고, 못 쌓는 큐는 확률 높은 순으로 보여 줍니다. 조건이 너무 커서 메모리를 넘으면 확률만 계산합니다.

### 12. 병렬 처리

- **Web Worker 풀**로 계산합니다. 워커를 못 쓰는 환경에서는 메인 스레드로 자동 전환합니다.
- **나누는 방식 두 가지**
  - 큐를 **첫 피스별**로 나눕니다.
  - **보드를 해시로** 나눕니다. 단계 m의 모든 보드는 정확히 K개 부분 중 하나에 속하고, 각 부분은 자기 소유가 아닌 보드를 버린 채 같은 scan/cull/place를 돌립니다. 부분들의 해법은 전체 해법 집합을 **분할**하므로 합치면 완전한 결과가 됩니다.
- 필요하면 부분 결과를 합친 마지막 작업을 워커 하나가 이어서 처리합니다.
- 워커 개수와 병렬을 못 쓴 이유를 화면에 표시하고, 메모리 보호용 안전장치로 너무 큰 계산은 확률만 계산하는 쪽으로 낮춥니다.
- 기기에 따라 쓰는 워커 수가 다릅니다(폰은 PC보다 적게 사용).

### 13. 자동입력 (큐 입력칸)

넥스트 입력칸은 괄호를 짝 맞춰 주는 **작은 편집 보조**를 가집니다. 입력 이벤트 하나를 보고 텍스트와 커서를 고치며, 계산 결과에는 영향을 주지 않고 **입력 문자열만** 바꿉니다.

**언제 동작하나**

- 글자를 **직접 쳤을 때**(`insertText`, 모바일 키보드의 조합 입력 `insertCompositionText` 포함)만 동작합니다. 붙여넣기, 삭제, 되돌리기, 코드로 값을 넣는 경우에는 건드리지 않아서 이미 쓴 큐가 바뀌지 않습니다.
- 방금 친 글자 `d`와 커서 위치 `p`, 그 앞의 텍스트만 보고 판단합니다. 고친 뒤에는 입력 이벤트를 한 번 더 보내 **경우의 수 표시와 `⚠` 경고가 새 문자열로 다시 계산**되도록 합니다.
- 피스 글자는 `I O T S Z J L`이며 대소문자를 구분하지 않습니다.

**규칙**

| 친 글자 | 조건 | 동작 | 예 |
|---|---|---|---|
| `[` | 항상 | 커서 뒤에 `]`를 붙이고 커서를 둘 사이에 둠 | `[` → `[│]` |
| `]` | 앞에 열린 `[`가 남아 있음 (`[` 수 > `]` 수) | 보정 없이 그대로 입력 | `[SZ` + `]` → `[SZ]` |
| `]` | 앞의 `[` 수 ≤ `]` 수 (짝이 없음), 앞이 `[]` + 피스 글자들 | 그 글자들을 빈 괄호 안으로 넣음 | `[]SZ` + `]` → `[SZ]` |
| `]` | 앞의 `[` 수 ≤ `]` 수 (짝이 없음), 앞이 피스 글자들 | 그 글자들을 `[ ]`로 감쌈 | `SZ` + `]` → `[SZ]` |
| `}` | 앞의 `{` 수 ≤ `}` 수 (짝이 없음), 앞이 순서 조건식 | 조건식을 `{ }`로 감쌈 | `[]!SZ>LJ` + `}` → `[]!{SZ>LJ}` |

- 열린 괄호가 남아 있는지는 **커서 앞 텍스트의 `[`·`]` 개수(또는 `{`·`}` 개수)** 를 세어 판단합니다. 개수를 비교할 뿐이라 중첩 괄호에도 같은 규칙이 적용됩니다.
- **순서 조건식**은 `글자들 <|> 글자들`이 하나 이상 이어진 것(체인 `A<B<C` 포함)이고, 쉼표로 여러 규칙을 이을 수 있습니다. 식 사이의 공백은 허용합니다. 이 식이 입력의 **맨 끝**에 있을 때만 `{ }`로 감쌉니다. 식이 아니면 `}`는 그냥 입력됩니다.
- 감싼 뒤 커서는 닫는 괄호 바로 뒤에 놓입니다. 그래서 이어서 숫자나 `!`를 계속 칠 수 있습니다.
- 자동 보정은 **입력 도우미**일 뿐이고, 문법 검사와 오류 안내는 따로 합니다(`⚠` 경고, 경우의 수 오류). 괄호가 맞지 않거나 규칙에 맞지 않는 입력은 그대로 오류로 알려 줍니다.

## PC solver와의 문법 비교

큐 입력 문법은 PC solver를 바탕으로 하되, 아래 부분을 **확장**했습니다. (PC solver의 문법에서는 지원되지 않는 것으로 파악한 내용이며, 도구나 버전에 따라 다를 수 있습니다.)

| 항목 | PC solver | 이 도구 |
|---|---|---|
| 7-bag 표기 | `[szljoit]!`처럼 일곱 피스를 전부 써야 하고 `[]!`로 줄여 쓸 수 없음 | `[]!` 한 줄로 기본 7-bag 지정 (`[]` = `[IOTSZJL]`) |
| bag 여부 뒤집기 `%` | 부가 문법 없음 | `%`로 bag 지정/해제. bag이면 PC 후 남는 bag 통계가 나오고, 해제하면 그 통계를 계산하지 않음 |
| 순서 조건 `{ }` | 부가 문법 없음 | `{LJ<SZ}`, `{SZ>LJ}`, 체인 `{A<B<C}`, 쉼표 `{A<B,C<D}` |

이 도구에서 추가로 제공하는 입력 기능입니다.

- `[]3!`처럼 bag에서 일부만 뽑기
- `[[SZ]! [LJ]!]2!` 같은 묶음 중첩
- `[` 입력 시 `]` 자동 추가, `SZ]` → `[SZ]`, `[]!SZ>LJ}` → `[]!{SZ>LJ}` 자동 보정
- 순서 조건에 묶음에 없는 피스를 쓰거나 일부만 뽑는 묶음에 조건을 쓰면 `⚠` 경고
- 입력하는 동안 경우의 수 표시, 너무 큰 입력은 미리 거절·경고

**표현력**: 이 문법으로 표현할 수 없는 큐는 없습니다. `[IT]2`는 고정된 큐 `IT` 하나이고, 이런 고정 큐들을 `[ ]`에 넣으면 그중 하나를 고르는 묶음이 되기 때문입니다. 예: `[[ITS]3 [JLO]3 [ZSI]3]`은 세 큐가 각각 1/3입니다. 같은 큐를 반복하면 가중치도 줄 수 있습니다. 규칙으로 설명되지 않는 큐 집합은 길어질 뿐입니다.

예를 들어 `T[]!{t>j}`처럼 한 줄로 "맨 앞 T + 7-bag, 단 bag 안에서 J가 T보다 앞"을 쓸 수 있습니다.

---

## 제한 사항

- PC 탐색은 **바닥 8줄**까지만 지원합니다.
- 보드 높이는 PC 찾기에서 최대 12줄, 구축 확률 모드에서 최대 23줄입니다.
- 경우의 수가 매우 많은 큐는 계산이 오래 걸리거나 메모리 보호를 위해 확률만 계산됩니다.
- 구축 확률 모드에서 12줄을 넘는 보드를 PC 찾기로 옮기면 높이가 12줄로 줄어듭니다.
- 길이가 다른 큐를 `[ ]`로 섞어 쓰면 가장 짧은 길이에 맞춰집니다.

## 크레딧

큐 입력 문법과 탐색 알고리즘은 기존 **PC solver**의 영향을 상당히 받았습니다. 해당 도구들을 만든 분들께 감사드립니다.
